# Codex Session Rescue

**Codex 会话救援助手：帮助恢复因历史加密状态重放失败而无法继续的本地会话。**

本地网页工具，面向部分 `invalid_encrypted_content` 报错场景。支持查找会话、检查主会话及子代理、预览清理范围、备份清理、同步历史索引和回滚。

运行时只使用 Python 标准库。检查与文件修复在本地完成；主动开启代理并接入会话后，请求会转发到你填写的原厂商 URL。工具不会解密或重新加密历史。

## 什么时候适合使用

如果已有 Codex 会话反复报 `invalid_encrypted_content`，重新打开后仍无法继续，而问题可能来自本地历史中被反复发送的加密状态，可以先用本工具检查。

账号池切换、服务提供方迁移或代理处理异常，可能导致之前保存的加密状态不再被当前上游接受。这些是潜在使用场景；单凭错误名称不能确定根因，本工具也不会推断密文绑定了哪个账号、组织或密钥。

| 情况 | 本工具的处理范围 |
| --- | --- |
| 已保存的加密推理历史导致旧会话反复报错 | 通过结构与索引检查后，可尝试备份清理 |
| 主会话、子代理或分段历史包含受支持的加密结构 | 可检查关联关系，并选择实际需要处理的会话 |
| 中转服务持续切换到不兼容的上游，或持续错误转换请求 | 清理本地历史不能消除根因，之后仍可能复发 |
| 当前上下文依赖纯加密压缩检查点，缺少可读替代历史 | 停止清理，无法承诺无损恢复 |
| 网络、登录、额度、限流或普通服务端错误 | 不属于本工具的修复范围 |
| JSONL 损坏、序号不连续、索引不一致或未知结构 | 停止检查或清理，需要另行处理 |

工具没有针对某个中转网站编写专用逻辑，但这不代表已经在所有网站、服务提供方或 Codex 版本上验证兼容。

## 如何恢复，以及清理的代价

处理流程：**退出要处理的会话及子代理 → 检查文件与索引 → 预览范围 → 保存备份 → 清理受支持的加密记录 → 同步索引 → 重新打开会话验证。**

- 识别并移除特定加密推理记录或加密内容块，包括受支持的嵌套历史和子代理消息。不同记录类型有各自的检查规则，不会对所有同名字段盲目删除。
- 清理时移除工具调用及厂商生成消息的服务端条目 `id`，保留 `call_id`、工具名称、参数、输出、消息正文和本地消息 ID。这样重放不再依赖原厂商资源中的条目。界面事件和可读工具记录保持原 ID。已清理过密文、仍保留厂商条目引用的会话也支持备份修复。
- 核对可读历史的保留情况。有可读摘要的加密推理记录，必须先确认存在保留副本，才允许移除对应记录。
- 已被后续明文历史替代的旧加密压缩检查点，可在满足检查条件时清理；当前仍依赖的纯加密压缩检查点会阻止清理。
- 清理后更新相关记录序号、文件位置和历史索引，避免文件与数据库不一致。

**存在加密内容不等于内容损坏。** 本工具无法离线验证密文是否失效，也不能准确定位哪一块导致服务端拒绝。通过检查，表示当前结构满足工具的处理条件，并不证明每个待清理的加密块都有问题。

**保留可读聊天记录不等于完整保留模型状态。** 被移除的加密推理状态不会被还原，模型后续的推理连续性或回答表现可能变化。清理是否解决报错，需要重新打开会话并发送消息验证。

报错记录是辅助提示，不是清理按钮的硬性条件；没有报错记录的会话也可能通过检查。建议仅选择实际无法继续、需要恢复的会话。

## 打开和使用

需要 Python 3.11 或更高版本。在项目目录运行：

```sh
python app.py --open
```

Windows 也可以双击 `Launch.cmd`；运行 `InstallShortcut.ps1` 可创建桌面快捷方式。当前界面与快捷方式名称仍为 **Codex 会话修复助手**。

1. 搜索会话 ID、粘贴 `codex resume …` 命令，或按标题、摘要、项目路径查找。搜索基于会话元数据，不搜索完整聊天正文。
2. **先退出要处理的 Codex 会话及相关子代理**，保持它们关闭，直到清理完成。工具不会自动结束 Codex 进程。
3. 在工具中选择会话，点击 **检查会话**。默认同时检查其子代理，包括下级子代理。若仍提示占用，先确认相关会话已退出，再重新检查。
4. 查看历史分段、加密块数量、索引检查结果与停止原因，勾选实际需要处理的会话。
5. 点击 **备份并清理**，等待操作完成。
6. 使用页面给出的命令重新打开会话，发送消息确认是否恢复。

## 当前会话代理

在会话详情的 **当前会话代理** 面板填写这条会话原来的 API URL，然后点击 **备份、清理并开启代理**。默认勾选 **一并处理子代理**，会同时备份、清理这条会话的现有子代理，过滤它们及后续新建子代理经过该入口的请求。取消勾选时只处理当前会话。API URL 可以填写基础地址（例如 `https://vendor.example/v1`）或完整的 `/responses` 地址。

开启后，用面板提供的 `codex … resume …` 命令重新打开这条会话。命令只为这次运行设置代理地址，沿用原厂商的凭据。现有桌面会话需要接入该代理地址才会生效；本版不会自动修改全局 Codex 配置。

代理根据 Codex 请求中的 `thread-id`、`session-id` 和会话元数据精确匹配规则。子代理归属从本地会话索引的父子关系读取，不根据聊天正文猜测。只有匹配且已开启的会话才过滤加密推理和受支持的加密内容块，并移除工具调用及厂商消息的服务端条目 ID。普通消息正文、工具调用内容、工具结果和可读推理摘要保留。其他主会话及关闭过滤后的请求按原内容转发到该入口所绑定的上游。已有子代理使用其他厂商入口时，仍需将该入口接入代理。

每条会话有独立的代理入口和上游 URL，可以同时使用不同厂商。面板显示已匹配请求数、移除加密块数和最近错误。规则与上游地址保存在 `%LOCALAPPDATA%/CodexSessionRepair/gateway-rules.json`，不保存 API 密钥、请求正文或回复正文。

本版支持 Responses HTTP 和 SSE 流式回复。恢复命令关闭 WebSocket 和远程加密压缩，避免后续请求依赖纯加密压缩记录。遇到已有纯加密压缩或服务端历史引用时停止转发，并给出原因。上游回复原样返回，之后新产生的密文仍能写入本地历史；它们在后续发送时过滤。

保持工具运行。退出工具后，使用代理地址的会话暂停请求；重新启动工具后继续。工具记住监听端口；若端口已被其他进程占用，页面会生成新的入口和恢复命令。点击 **关闭密文过滤** 只关闭过滤，继续转发到原厂商；要完全绕过工具，使用普通的 `codex resume …` 命令重新打开。

## 备份、回滚与中断恢复

- 每批操作先保存所有选中会话的原文件、修复副本、索引快照与文件校验信息。
- 选中的主会话和子代理一起持有写入锁，在同一 SQLite 事务中更新对应历史索引。
- 文件替换发生错误时，回滚已经替换的文件和未提交的索引。
- 在 **修复记录** 中可以导出 ZIP 备份，或点击 **回滚到清理前**。
- 如果清理后已经出现新消息，工具会阻止覆盖式回滚，避免覆盖新的会话进度；备份仍然保留并可导出。
- 遇到断电或进程中断留下的未完成操作，记录页提供 **恢复清理前状态**。只有当前文件和索引能与已保存快照对应时才会恢复。

备份保存在所选 Codex 数据目录的 `backups_state/tool-…`。工具也能读取兼容的早期独立/分段修复备份，不自动删除备份。备份包含原始会话数据，提交公开 issue 时请勿附上未经脱敏的备份或聊天文件。

## 兼容范围

### 会话结构

- 独立会话、同一逻辑会话回滚形成的多段历史。
- 子代理树，以及父会话中转存的子代理加密消息。
- `guardian_history`、`replacement_history` 等嵌套历史中的受支持加密结构。

其他会话共享的基础历史、尚未完整同步的历史索引、不连续的序号、当前仍依赖的纯加密压缩检查点和未知格式，都会阻止处理。检查结果不会替代对清理代价的判断。

### Codex 版本与数据格式

当前实现依赖 `state_5.sqlite`、`thread_history_1.sqlite`、对应表结构和 JSONL 历史格式。这些应按 Codex 内部存储实现对待，不能假定它们是稳定的公共接口。

当前没有自动选择不同存储版本的适配器，也尚未建立按 Codex 发布版本维护的兼容列表。数据库文件名相同不代表结构一定兼容；工具会检查所需条件，但这不构成对所有版本的兼容保证。

仓库测试覆盖的是代码中构造的合成数据结构，不等于已经验证所有真实环境。报告兼容性问题时，可以提供 Codex 版本、操作系统和脱敏后的检查错误，帮助补充可复现的兼容记录。

### 操作系统

- Windows：提供 `Launch.cmd` 和 PowerShell 快捷方式安装脚本。
- macOS / Linux：Python 代码包含非 Windows 的文件锁分支，可以从命令行启动，但尚未完成平台兼容验证。

## 数据与运行配置

- 默认会话目录：当前用户主目录下的 `.codex`，由 `Path.home()` 获取，没有固定用户名或盘符。自定义数据目录请显式传入 `--home`；当前实现不自动读取 `CODEX_HOME` 环境变量。
- 工具自身日志与启动记录：默认位于 `%LOCALAPPDATA%\CodexSessionRepair`；没有 `LOCALAPPDATA` 时使用用户主目录下的 `CodexSessionRepair`。可用 `--data-dir` 修改。
- 服务仅监听 `127.0.0.1`，有请求来源、Host 和操作令牌检查。
- 页面右上角 **退出工具** 会停止后台服务；正在处理时禁止退出。

指定会话目录、工具状态目录和端口，例如在 Windows 上：

```powershell
python app.py --home "C:\path\to\.codex" --data-dir "C:\path\to\tool-state" --port 8765 --open
```

省略 `--port` 时优先复用上次端口；首次启动或上次端口被占用时选择可用端口。
